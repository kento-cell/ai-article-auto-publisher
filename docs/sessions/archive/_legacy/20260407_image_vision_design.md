# 2026-04-07: 画像認識・品質保証設計

## 背景

- 現状のImageSourcerは画像をAPIで取得するだけで、関連性・品質を判断する能力がない
- ユーザーは記事内容を確認しない（タイトル+スコアのみで判断）
- 画像が陳腐/無関係だと品質に直結する
- Criticが画像をVisionなしでディスカッションしても無限ループ→トークン浪費

## 決定事項

### 画像認識パイプライン（全ローカル・コスト0円）

```
ストック写真候補
  → [1] Pillow: 解像度 ≥ 1200×630
  → [2] BRISQUE (pyiqa): 品質スコア < 50
  → [3] CLIP (日本語): 画像-記事テキスト類似度 > 0.25
  → [4] Ollama Qwen2.5-VL: 日本語キャプション生成 + 関連性確認
  → 採用
```

### 依存パッケージ

```
pip install Pillow open-clip-torch pyiqa ollama
ollama pull qwen2.5vl
```

### 運用環境

- 自宅ゲーミングPC（GPU強い）で実行
- このPC（会社PC）では設計・コード作成のみ

### Criticの画像チェック範囲

Stage 1-4を通過した画像のみ記事に入る。Criticは画像自体を見ない。
テキストベースのチェックのみ:
- キャプション（日本語）の有無
- alt_textの適切さ
- プレースホルダー混入なし
- 視覚要素数

### 画像使い分け

| 用途 | ソース | 関連性保証 |
|------|--------|-----------|
| 技術概念 | Mermaid図（自作） | ✅ 確実 |
| データ比較 | テーブル（自作） | ✅ 確実 |
| 実装例 | コードブロック | ✅ 確実 |
| ヒーロー画像 | ストック写真（Stage 1-4通過） | ✅ 検証済み |
| セクション画像 | ストック写真（Stage 1-4通過） | ✅ 検証済み |
