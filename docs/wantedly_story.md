# AIが記事を書く時代に、「質」をどう担保するか — note/Zenn 自動投稿システムを自作した2週間

「AIで記事量産」は、もう珍しくない。Google で検索すれば、ChatGPT に流し込んで公開するだけのブログが溢れている。

でも、**AI生成された記事の90%は読者に届かない**。理由はシンプルで、読みに行っても、3行で「中身が薄いな」と感じて離脱されるから。作る側は一瞬だが、読み手の時間を盗んでいる。

だから、記事を大量に出すほど、**質を担保する仕組み**のほうが重要になる。そういう問題意識で、2週間かけて note / Zenn の自動投稿システムを自作しました。

## 開発の背景

AI 記事生成ツールは、大きく3つの層に分かれます。

1. **収集層**: トレンドの題材を拾う (RSS, arXiv, Reddit, Google Trends)
2. **生成層**: ローカル LLM (Gemma3) で下書きを書く
3. **判定層**: 公開に耐えるか採点する

世の中のツールは 1 と 2 に注力していて、3 がおろそかです。結果として「誰が書いても出てくる平均的な記事」が世界中に量産される構造になっている。

私が作ったシステムは、**3 の判定層を2段構え**にしています。

- 客観スコア: 引用数 / 一次ソース比率 / 視覚要素 / チェーン店検出 / 禁止フレーズ → プログラムで機械判定
- 主観スコア: LLM に独自性・正確性・可読性・タイトル-本文一致を採点させ、各軸に根拠文を強制出力

どちらかが C 評価 (不合格) なら、その記事は公開されない。2 を何度もリトライさせる自動再生成ループも組み込みました。

## 失敗から学ぶ仕組み

開発2週間目、重大なインシデントが起きました。「習近平氏の Bluesky 投稿を徹底分析」という note 記事が公開された。**Bluesky に習近平のアカウントは存在しない**。ローカル LLM が、Google Trends のキーワードから架空の前提を作り上げていたのです。

同様のハルシネが、妻夫木聡・メッツ・李在明で次々発生。判定層があっても、「固有名詞の実在検証」はスコアリングだけでは難しいと痛感しました。

対策として、**3段ガード**を導入しました。

1. 生成段階: 禁止フレーズ集を強化 (「〇〇氏の Bluesky 投稿」「がトレンド入り」等の架空パターン検知)
2. 承認段階: overall_grade=C の自動承認を拒否
3. 投稿段階: 最終タイトル・本文スキャンで deny パターンを検出、該当記事は投稿を停止しステータスを却下に変更

同時に、既に公開してしまった架空記事は、**一次ソース確認した事実ベース**に全面差し替えました。記事を消すのではなく、透明な訂正ノートを付けて再構築する。AI が書いた記事の信頼性を守るのは、AI ではなく運用する人間の責任です。

## 自己学習ループ

もう一つの柱が「自己学習」です。単に生成して投稿するだけでは、システムは学ばない。

そこで note の人気記事を毎日スクレイピングし、タイトル・タグ・フレーズ構造を抽出。過去7日分を移動平均で統合して、次回の生成プロンプトに「これが今読まれている形」として注入する仕組みを組みました。

さらに、生成した記事が学習パターンをどれだけ採用したかを測定。【〇〇】系ブラケット採用率・フレーズヒット数・タグ一致率をスコアに記録し、A/B テストで「どのプロンプト改修が実効的だったか」を事後検証できるようにしました。

これで、**運用すればするほど記事の質が自動で上がる**閉ループが完成しました。

## 結果

2週間の運用実績:

- Zenn: 40本以上 (技術記事 + スクラップ)
- note: 累計46本、うち高品質化した訂正版 6本
- 自動で却下されたハルシネ記事: セッション中に 10件以上
- GitHub PR: 1本、12コミット、Codex 独立レビュー通過

独立レビューでは Codex (GPT-5.4) にセキュリティ観点でレビューさせ、CRITICAL 2件・MAJOR 4件・MINOR 4件の指摘を受けて全て修正。path traversal / SSRF / リダイレクト bypass / リソースリークなど、個人開発で見落としがちな観点を含めて潰しました。

## 次の展開

このシステムをベースに、2026年5月から note のメンバーシップ (月額制サブスクコミュニティ) を開設します。メンバーには、改修ログ・プロンプト差分・収益データの生公開・ソースコードアクセスを継続提供します。

「動いている実装の現場記録」自体を商品にすることで、他のAI副業コンサルにはない差別化を作る。AI 時代に「書く」から「仕組みを育てる」へ、私自身の働き方をシフトさせている最中です。
