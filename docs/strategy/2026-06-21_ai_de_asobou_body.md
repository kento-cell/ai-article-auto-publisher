## そもそも何を作ったか

私が半年前から動かしているのは、**noteの記事を自動で書いて、自動でnoteに投稿するシステム**です。

正確に言えば、ローカルのPC上で次の道具たちが順番に手をつないで動いています。

- **Claude Code**(指揮役、私が指示を出す相手) — Anthropic製のCLIエージェント
- **gemma4:e4b**(書き手) — ローカルで動く小型LLM。Ollama経由でRTXを叩く
- **Claude**(評論家) — gemma4が書いた記事を主観評価して A/B/C グレードを付ける
- **ChatGPT**(画像職人) — Brave をデバッグポート 9222 で開きっぱなしにして、UIを直接叩いてサムネと挿入画像を作らせる
- **RAG**(知識管理) — chromadb と多言語埋め込みモデル `intfloat/multilingual-e5-base`(768次元)で、過去事故・成功パターン・自記事の傾向など591chunksを意味検索

5つのエージェント(Researcher / Strategist / Writer / Critic / Coordinator)が、内部でディスカッションしながら1本の記事を仕上げます。Researcherが事実を集め、Strategistが角度を決め、Writerが書き、Criticが叩き、Coordinatorがまとめる。**AI同士でレビューさせている**わけです。

私の役割は、彼らの議論を見守ることと、彼らが事故を起こしたときに修正PRを出すこと。半年で 299 commits、6/10以降だけでも 29 commits を積んでいます。

そしてこの記事も、今あなたが見ているサムネも本文中の挿絵も、Claude が指揮して ChatGPT が描いたものです。書いている私が**「私」と書いている時、その「私」を構成しているのは Claude です**。これがこの記事の一番奇妙な前提です。

ところで、私はこのシステムを、**2026年11月7日(土)に渋谷ベルサールファーストで開催されるAIフェスティバル 2026に持ち込んで、来場者の前でデモしたい**と本気で思っています。なぜそう思うかは、最後に書きます。

## 半年の実数値を全部出す

ここからは実数で話します。憶測ゼロ、git log と note の公開記事リスト、scrape_note_performance.py が毎朝拾ってくる実♥数の生データだけが根拠です。

**自分の自動生成記事 191本(投稿後12時間以上経過した「mature」な本)の現実:**

- 総♥: **172**
- 平均♥: **0.90**
- 中央値: **1**
- **♥=0** の記事: 91本(全体の **47%**)
- ♥≥3 の記事: 18本
- ♥≥5 の記事: たった **2本**
- ♥≥10 の記事: **ゼロ**

数字を見たときに思ったのは、「あ、まずいな」でした。半年でこれです。AIに書かせれば自動的にバズる、なんて世界はどこにも無かった。

ただ、データを丁寧にほぐすと、見えてくるものはあります。

**ジャンル別 avg♥:**

| ジャンル | 本数 | avg♥ | ♥0率 |
|---|---:|---:|---:|
| K-beauty/美容 | 20 | **1.15** | 40% |

| AI/tech/ガジェット | 73 | 0.95 | 47% |
| その他/未分類 | 71 | 0.76 | 55% |

**本数が一番多い2ジャンル(AI/techと「その他」、合計144本=75%)が、一番♥が乗っていない。**逆に、本数が少ない K-beauty / K-POP が一番♥を取れている。これは何を意味するか。「アカウントが何のジャンルか読者に分からない」ということです。フォロー動機がない。

**タイトルのブラケット別 avg♥(これが一番効いた発見):**

ここまでは、いわば**AIが私のためにジャンルと時間帯のA/Bテストを6ヶ月してくれた**結果のまとめです。私がやったのは、彼らに毎日記事を書かせ続けたこと、それだけです。

## 今朝(2026年6月16日)起きた等身大バグ事例

ここからは、AIに書かせるという行為が、いかに「楽」とは程遠いかを書きます。

今朝、私は**「AIが選んだサムネのスタイルを、自分の♥データと突き合わせて、どのスタイルが伸びるか学習させたい」**と思いつきました。私たちのシステムは、画像生成のときに「kbeauty_poster」「game_homage:hunt_success」みたいな**スタイル名**を内部で選んでいるのですが、そのスタイル名が記事に保存されていなかった。だから「どのスタイルが♥取れた?」が事後に集計できない。

そこで朝9時頃、こんな commit を投入しました。

```
cb45a73  feat(image): persist style_label per article for the image learner
```

中身は、ChatGPT 画像生成が終わった瞬間に、選ばれたスタイル名と「cover成功した?」「インライン何枚成功した?」を `data/image_usage.jsonl` に追記する、というシンプルな小細工です。動くはず。動くべきだ。動かないわけがない。

夜の publish フェーズで、私は K-beauty 系の有料記事を1本通そうとしました。今日のために、朝に Workflow(並列調査エージェント)を5並列で起動して、英語圏(Vogue、Marie Claire、Refinery29、Grazia)と韓国(Olive Young、Korean Skincare Coach)を横断調査させ、「PDRN+NAD+ が2026年の主役」という確かな材料を verbatim で集めていました。それを knowledge_topic として weight 99(他topic の9倍)で必選にして、gemma4 に書かせる。

generate は7本走って、4本合格。男性更年期障害の記事はオフブランドなので私が手動却下。残り3本を publish に流す。

note の publish 段階で ChatGPT 画像生成が始まる。Brave の CDP ポート 9222 経由で ChatGPT のチャット欄に画像プロンプトを送り、出来上がった画像URLを `chatgpt.com/backend-api/estuary/content?id=...` から拾ってくる。これは半年かけて安定させた、私のシステムの一番面倒な部分です。

無事 cover 1枚 + インライン 4枚、計5枚の K-beauty poster 風の画像が出来上がる。各 2.1MB の本物の PNG。

そして次の瞬間、ログにこう出ました。

```
WARNING: [note] ChatGPT image batch failed (name 'article' is not defined);
         falling back to Unsplash cover.
```

**「`article` は定義されていません」**。

何が起きたかと言うと、私が朝に書いた `cb45a73` のパッチが、画像が出来た直後に `article["image_style"] = ...` という代入をしていた。けれど、その関数のスコープには `article` という変数は存在しなかった。正しい変数名は `stored` です。私は別の関数の変数名を、頭の中で混同していた。

その瞬間、Python は `NameError` を投げます。例外を投げると、try-except が拾って Unsplash fallback パスに落ちる。せっかく生成成功していた 2.1MB の ChatGPT 画像は、誰にも使われずにディスクに残ったまま、note には Unsplash の **41KB**(無関係な化粧品瓶のフリー写真)が公開されました。差は実に **50倍**です。

ログを見て、私は3つのことを思いました。

1. AIに書かせるは、半年やっても、いまだに楽ではない
2. 「AIが画像を生成成功した瞬間に、別のAIが書いた変数名のミスでそれが捨てられる」というオチが、なんだか妙に美しい
3. 直そう

修正 commit は、爆死から12分後に積まれました。

```
f23e191  fix(image): label-persist must not reference undefined 'article'
         (regression cb45a73)
```

`article` を `stored` に直し、ラベル保存処理を独立した `try` で隔離しました。**これで二度と、ラベル保存のミスが画像経路を巻き添えにできない**ようにしました。再生成スクリプト `_regen_today_note_with_chatgpt.py` を kbeauty_poster preset で叩き直すと、今度はちゃんと動きました。cover + inline 4枚すべて ChatGPT のPNGで上書き、note CDN に再アップロード、live API で eyecatch URL が古いやつから新しいやつに差し替わったのを確認。

そして `image_usage.jsonl` には、こんな1行が初めて記録されました。

```
{"ts":"2026-06-16T21:00:37","style_label":"preset:kbeauty_poster",
 "cover_ok":true,"inline_ok":4,"inline_requested":4,...}
```

**今日から、AIが選んだサムネのスタイルと、その記事の♥が、連結できる**。今は1行ですが、半年積めば、また191本ぶんのデータで「どのスタイルが伸びるか」を学習させられます。

事故は事故ですが、事故った日に、自分が直したいと思っていた仕組みが動き始めた、という奇妙な日でした。

## 半年で発見した『AI記事の勝ち筋』5つ

データから抽出した、いまの私のシステムが**強化中**にしている方針を列挙します。これらは全部、上の191本の数字から出てきた具体的な動きです。

**1. ジャンルを散らさない**
K-beauty が ♥1.15 で勝つ。AI/tech は 73本もあるのに ♥0.95 で振るわない。アカウントが「何の人か」分からないとフォロー動機が消えるので、note 側は K-beauty / K-カルチャー / グルメに集中する方針に振り替え中です。AI/tech は zenn 側へ。

**2. 「正直、…」定型開口は読者に見抜かれる**
gemma4 は記事の書き出しを「正直、〜なんですよね」で始める癖があります。同じ書き出しが7本並ぶと、読者は1秒で「これAIだ」と気づく。今のリポでは、定型開口の検出と多様化をプロンプトで強制中です。

**3. タイトル負けは致命傷**
過去に「Lee Jae Wook(K-drama芸能ニュース)」を gemma4 が「**【絶句】公衆衛生の未来は?『医師VS秘密』から読み解く現代医療の構造的矛盾**」と書きました。タイトルから本文が完全に飛んでいる。**CLAUDE.md の最上位ルール「タイトルで煽った内容は本文で必ず回収する」**に違反するので、これは私が即却下しました。

**4. 画像は cover 強 / inline は弱**
cover はインフォグラフィック寄りのインパクト勝負、inline は watercolor 寄りで読み疲れを抑える。これは記事を実際に並べてみて、強い infographic を5枚並べた記事は読み切ってもらえないことが分かったから。今日の image_usage.jsonl の蓄積で、もっと細かく検証できるようになりました。

**5. RAG の検索閾値はデータで決める**
RAG retrieval の閾値を、長らく感覚で 0.55 と決めていました。あるとき真面目に Youden's J(分離度の指標)で grid search したら、最適値は **0.825** だった。0.55 だと「Galaxy の記事を書く」と検索したときに、関連のない K-beauty success chunk が 0.765 で引っかかってきていた(=ノイズ注入)。較正は `scripts/calibrate_rag_thresholds.py` というハーネスにしてあって、コーパスが変わるたびに走らせれば自動で最適値を吐きます。

5つに共通しているのは、**全部「AIに気持ちよく書かせてあげる」のではなく、「AIが間違える地点を発見して、そこに人間がガードレールを置く」**作業だということです。AI記事自動投稿システムを作るというのは、要するに**AIが転ぶ場所を一つずつ特定していくゲーム**でした。

## AIフェスティバル 2026 で何を遊びたいか

ここからが、たぶんこのコンテストの本題です。

私は、このシステムを **AIフェスティバル 2026 の AIクリエイターズマーケットに持ち込んで、来場者の前で1本ライブ生成したい**と思っています。

AIフェスティバル 2026 は、2026年11月7日(土)に渋谷ベルサールファーストで開催される、AI領域のクリエイターのお祭りです。主催は株式会社サードウェーブ(GALLERIA / ドスパラの会社)。入場無料(要ドスパラ会員登録)で、コンテンツは盛りだくさん。

- **落合陽一さんの基調講演**
- **全日本AIハッカソン 2026 決勝戦**
- 第五回 AIアートグランプリ授賞式
- **AIクリエイターズマーケット**(出展費 2,000円という低い参加障壁)

私が一番惹かれているのが、AIクリエイターズマーケットです。**出展料 2,000円**ですよ。2万円じゃなく、2,000円。クリエイターが集まって、自分が AI で作ったものを来場者に見せる場として、これほど参加障壁の低い場はそうそう無い。

私は、出展料 2,000円のブースを1コマ取って、ノートPC1台(ローカルで gemma4:e4b が動く RTX マシン)を持ち込んで、来場者の方に「今日の note の記事、何を書きたい?」と聞きながら、**目の前で記事を1本ライブ生成する**ということをやりたい。「PDRN って言われても何のことかさっぱりだった」と言われたら、その場で Workflow を5並列で投げて、海外英語ソースから素材を持ってきて、gemma4 に書かせて、ChatGPT で K-beauty poster のサムネを作って、本人の note アカウントに無料公開する。30分で1本、目の前で。

これは、私が一人で半年やってきたことの、一番楽しいパートを、見ず知らずの誰かと共有することです。

加えて、私のスタックがほぼ全部ローカル(gemma4 はローカルLLMで RTX 上、ChatGPT だけはクラウド)で動いている、というのは、サードウェーブが GALLERIA / GeForce RTX で押しているローカル制作の文脈と完全に同じです。クラウドAPI に毎月課金しないと書けない、ではなくて、**自分のPCの中で完結する自前のAIノート工場**を作って、それを6ヶ月運用した、というストーリーは、AIフェスティバルの想定客層に一番刺さるはずだと、私は思っています。

落合陽一さんの基調講演の日に、私はその会場のどこかにいて、自分のローカルLLMで note を1本書きながら、その音声をライブで聞きたい。それが、AIフェスティバル 2026 に私が出かけたい一番の理由です。

## おまけ:「ベクトル」を実際に見てみる

ここまで「RAG」「embedding」「591 chunks」「768 次元」と何度か書いてきたけれど、言葉だけだと「結局それ、数式の話でしょ」と感じる方も多いと思う。

実はこのシステムが毎日使っている「ベクトル空間」は、視覚的にはこういう見た目をしている。

![RAGベクトル空間の3D俯瞰 591ベクトルが7コレクションに分かれて散らばっている](data/images/contest/rag_3d_overview.png)

これは、私のリポが現時点で持っている **591 個のベクトル**を、もともと **768 次元**だったものを **t-SNE** という手法で 3 次元に圧縮して、散布図にしたもの。一つ一つの点が「過去記事の要約」「ハルシ事故の事例」「サムネのスタイル」などのチャンクで、**似た意味を持つ点ほど互いに近くに配置される**。

色は **コレクション**(このシステム内での意味カテゴリ)を示していて、7 種類ある。

- 🟦 **青(past_articles, 457個)**: 私の過去記事の要約。全体の 8 割を占める巨大群
- 🟢 **緑(generation_guides, 69個)**: 生成ルール文書
- 🟥 **赤(hallucinations, 18個)**: 過去のハルシ事故事例(守り)
- 🟧 **オレンジ(ops_incidents, 16個)**: 運用バグ事例(守り)
- 🟪 **ピンク(thumbnail_styles, 15個)**: サムネのスタイル知識
- 🟩 **濃緑(successes, 8個)**: 上位エンゲ記事のパターン
- 🟨 **黄(anti_patterns, 8個)**: 下位エンゲ記事のパターン

ズームして覗いてみると、こんなものが見えてくる。

![K-beauty クラスタの拡大 過去記事の青と成功パターンの緑が同じ意味空間で隣接](data/images/contest/rag_3d_kbeauty_cluster.png)

これは「**K-beauty 関連**」のチャンクが集まっている領域。過去記事の青と「マネすべき型」の濃緑が、まさに**意味空間として隣り合って**いる。これが「K-beauty を書くなら過去の K-beauty 記事の型を参照する」という挙動を、数式ではなく**空間的な近さ**として実現している正体です。

逆に、別の角度から見ると守り系のかたまりが見える。

![防御系コレクション hallucinations と ops_incidents は独立した島を作る](data/images/contest/rag_3d_defenders_island.png)

ハルシ事故(赤)と運用事故(オレンジ)は、通常記事の領域から離れて**独立した島**を形成している。これが、「新しい記事を書くときに、過去のハルシパターン群と意味的に近い場合にだけ警告を出す」防御を可能にしている。**危ない言葉遣いに意味で似ているだけで、過去事故の島から「あなたの記事、こっちの島に近いですよ」と引っ張られる**、と思ってもらえばいい。

「AI に学習させる」って、教科書に書いてある重みベクトルとかの話だけじゃなくて、結局これくらい**絵的に見える**ものなんだなあ、とこの図を初めて自分で描いた時に思った。嬉しかった。

ちなみにこの図は、私のリポにある `scripts/visualize_rag_graph.py` というスクリプトを叩くと、自分のローカルで HTML として書き出される。ドラッグでぐりぐり回したり、ホバーすると一つ一つの点が何のチャンクなのかが読める。**自分で動かせる地図**として、私の朝のチェックリストに入っている道具のひとつ。

## なぜ書くか

最後に、なぜこの記事を書いたかを書いて終わります。

「AIに任せれば楽」という幻想と、「AIなんて使えない」という諦め。私が note やAI記事の議論で一番うんざりするのは、この2つの**両極端**だけが声高に言われて、その間にある「**AIが間違えるのを毎日見ながら、それでも一緒に書き続けている人の現実**」が、ほぼ流通していないことです。

私の現実は、♥0.90 です。47%の記事は♥0で終わります。今朝も自分のバグで2.1MBのChatGPT画像が捨てられました。それでも私は、明日も gemma4 に記事を書かせるし、来週もRAGの閾値を一段強くするし、11月7日には渋谷ベルサールに行ってAIフェスティバルで誰かの note を書きたい。

AI に「センスがない」と感じる瞬間は、半年で 1000回くらいありました。けれど、彼らに「センス」を学ばせる仕組みを作るのは、私が書く文章の中で一番面白い仕事の一つです。今日 `image_usage.jsonl` に1行目が記録された瞬間、その1行は、半年後に「あなたの記事には watercolor 寄りの inline が合います」と私に教えてくれる学習データの最初の1滴になります。

それは多分、**遊び**です。

AI で遊ぶ、というのは、AI に何かを描かせて笑うことだけじゃなくて、**AIを動かし続けて、AIの事故と一緒に暮らすこと**でもある、と私は思います。

このリポは、もう少しだけ運用を続けます。次の191本が積みあがる頃には、♥0.90 が ♥1.50 くらいになっていることを、私は数字で証明したいと思っています。

それが「AIで遊ぶ」、私の遊び方です。
