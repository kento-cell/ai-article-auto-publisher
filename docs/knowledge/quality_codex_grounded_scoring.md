# Quality Pattern — Codex-grounded 記事のスコアリング調整

_記録日: 2026-04-14_

## 背景

Codex web-search で事実根拠を固めた note 記事が、従来の `ObjectiveScorer`
基準で繰り返し C 判定（自動却下）を食らっていた。
原因は記事の品質ではなく、**スコアラー側が旧来の Ollama 生成を前提にした閾値**だったこと。

## 観測されたミスマッチ

| 指標 | 旧ブロッキング閾値 | Codex-grounded 実態 | 対応 |
|------|------------------|--------------------|------|
| `citation_count` | 5件以上で A、0-1 で C→却下 | 根拠は research brief 経由で本文に織り込まれ、`## 参考文献` の markdown リストを持たないことが多い | **ブロッキングから除外**。スコアは算出するが自動却下はしない |
| `word_count` | 2000-4000 外で C | 事実に忠実な分、1300-1900 字で収まる記事が多発 | 受容帯を **1300-4500** に拡大（A帯 2500-3500 は維持） |

## 適用箇所

`generators/objective_scorer.py`:
- `metrics_to_check` から `citation_count` を除外
- `_score_word_count` の受容帯を `accept_min=1300 / accept_max=4500` に調整

## 教訓

生成パスを差し替えたら、スコアラーの前提も合わせて見直すこと。
**生成品質が変わらないのに却下率が跳ね上がる** = スコアラーの閾値が旧世代に固定されているサイン。

citation_count を完全に無視するのではなく「ブロッキングから外して参考値として残す」
のが肝。将来 Ollama 系パスが復活したときに閾値を戻しやすい。
